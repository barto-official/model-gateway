Use coonvetnional commits rules from this repo: `@.cursor/rules/conventionall-commits.mdc`

and create logical commits based on my branch. Don't push. Use simple, straightforward language so users and other developers will understand it. Don't use jargon or obfuscated language.

Description of the commit should be a maximum of 2 bullet points. Description should not use any informtion that comes from internal discussion between developer and an agent. For example, if developer created a roadmap for agent from 0 to 10, agent shuld not mention in commit that it's the step number 4. Rather it should contain what outside users/customers should not about his change: high level overview.

Commit should be created with the audience in mind: clear, clean, succinct. Avoid verbosity.
